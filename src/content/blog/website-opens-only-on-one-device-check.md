평소 보던 사이트 하나만 열리지 않으면 인터넷이 끊겼다고 생각하기 쉽습니다. 하지만 다른 사이트와 메신저는 정상이고 특정 주소에서만 오류가 난다면 **전체 연결 장애보다 접속 대상·브라우저·네트워크의 차이**를 살펴야 합니다. 여러 설정을 한꺼번에 초기화하는 것은 원인을 찾는 데 별 도움이 되지 않습니다.

지금 할 일은 세 가지 비교입니다. **다른 사이트도 열리는지, 같은 사이트가 다른 기기에서는 열리는지, 같은 기기에서 연결만 바꾸면 열리는지**를 기록하세요. 결과에 따라 다음 행동이 달라집니다. 로그인 정보나 저장한 북마크를 지우기 전에 작은 시험부터 진행할 수 있습니다.

## 오류 화면에 적힌 말부터 구분해야 하는 이유

'페이지를 찾을 수 없음', '연결 시간이 초과됨', '보안 연결이 안전하지 않음', '접근이 거부됨'은 모두 화면이 안 뜬다는 점에서 비슷해 보여도 같은 상태가 아닙니다.

주소가 바뀌었거나 페이지가 삭제된 상황이라면 네트워크를 바꾸어도 해결되지 않습니다. 반면 서버 응답이 늦거나 연결 자체가 되지 않는 상황은 일시적인 사이트 장애와 내 연결 환경을 함께 의심할 수 있습니다. **인증서·보안 경고가 나온다면 경고를 무시하고 계속 접속하지 마세요.** 중요한 계정이나 결제 정보를 입력해야 하는 사이트일수록 공식 주소와 안내부터 확인해야 합니다.

오류 문구, 시각, 접속 주소의 도메인 부분을 적어 두면 재시도할 때 비교가 가능합니다. 오류 화면에 표시된 전체 URL에 개인 식별 정보가 들어 있다면 그대로 다른 사람에게 공유하지 않는 것이 안전합니다.

## 한 사이트의 문제인지, 내 기기만의 문제인지

같은 브라우저에서 신뢰할 수 있는 다른 사이트 두 곳을 열어 보세요. 두 곳 모두 열리지 않는다면 특정 웹사이트 문제로 좁히기 어렵습니다. 와이파이 연결, 비행기 모드, 공유기 상태처럼 기본 네트워크부터 살펴야 합니다.

다른 사이트가 정상이라면 문제가 난 주소를 **공식 홈페이지 첫 화면부터 다시** 열어 봅니다. 검색 결과의 오래된 하위 페이지나 즐겨찾기 주소만 실패하는 경우도 있습니다. 주소창에 비슷하게 생긴 철자가 끼어 있지 않은지, 자동으로 낯선 주소로 이동하지는 않는지도 확인하세요.

가능하면 같은 사이트를 다른 기기에서 열어 비교합니다. 다른 기기도 동시에 실패한다면 사이트 쪽 문제일 가능성이 올라갑니다. 이때 앱 삭제나 휴대폰 초기화로 해결하려 하기보다 사이트의 공식 공지나 고객지원 경로를 확인하는 편이 합리적입니다. 단, 한 번의 비교만으로 서버 장애라고 확정할 수는 없습니다.

## 브라우저만 바꾸었는데 접속된다면

같은 기기와 네트워크에서 **다른 브라우저**로 접속해 보세요. 이때 새 브라우저에서 정상이라면 기존 브라우저의 쿠키·저장된 세션·확장 기능 등 차이를 살펴볼 근거가 생깁니다.

다만 바로 '모든 인터넷 사용 기록 삭제'를 누르지는 마세요. 전체 쿠키 삭제는 여러 사이트에서 로그아웃을 유발하고 일부 설정을 초기화합니다. 가능하다면 문제 사이트의 데이터만 따로 관리하는 기능을 찾고, 로그인 복구 수단이 있는지 확인한 뒤 변경하세요. 시크릿 모드에서도 비교는 가능하지만, 시크릿 모드로 열린다고 해서 원인이 반드시 쿠키라는 뜻은 아닙니다. 확장 기능과 저장된 세션을 함께 다르게 사용하는 환경일 수 있습니다.

브라우저의 보안 경고가 계속된다면 캐시 삭제로 경고를 없애는 데 집착하지 말고 주소·기기 시각·공식 공지 등을 확인하고 해당 서비스에 문의하세요.

## 와이파이에서는 안 되고 모바일 데이터에서는 열린다면

동일한 기기, 동일한 주소, 동일한 브라우저를 유지한 채 **연결 방식 한 가지만** 바꾸어 비교합니다. 와이파이에서 실패하고 모바일 데이터에서 성공한다면 접속 경로가 서로 다르다는 단서를 얻은 것입니다. 공유기의 일시적 연결 문제, 네트워크별 차단, DNS(주소를 실제 서버 위치로 찾는 기능) 등 여러 가능성이 있지만 이 결과만으로 한 원인을 단정할 수는 없습니다.

공용 와이파이에서는 별도 로그인 화면을 통과해야 외부 사이트에 접속할 수 있는 경우도 있습니다. 다른 웹사이트까지 막혀 있다면 [공용 와이파이 로그인 화면이 안 나올 때의 점검 순서](/blog/public-wifi-login-screen-not-showing/)가 더 적합합니다.

VPN이나 별도의 보안 DNS를 사용 중이라면 해당 설정이 있는지 기록하세요. 회사·학교에서 관리하는 보안 설정을 임의로 끄거나 우회하지 말고 관리자에게 오류 문구와 비교 결과를 전달해야 합니다. 개인 기기에서도 보안 기능을 통째로 끄는 방식은 문제의 범위에 비해 위험이 큽니다.

## 접속이 돌아왔을 때도 점검할 한 가지

페이지가 다시 열리더라도 **로그인과 실제 기능까지 정상인지** 확인해야 합니다. 첫 화면은 보이는데 결제·파일 다운로드·인증 화면만 실패한다면 사이트 전체 접속 문제와는 다른 문제일 수 있습니다. 다른 브라우저에서 열리는지, 로그인 이전과 이후에 차이가 있는지 구분하면 문의 내용이 명확해집니다.

장애가 오래 이어지거나 반복된다면 서비스에 '언제, 어느 주소, 어떤 브라우저, 와이파이와 모바일 데이터에서 각각 어떤 결과였는지'를 전달하세요. 여러 조치를 시도했다는 설명보다 비교 조건이 적힌 짧은 기록이 원인 조사에 도움이 됩니다. 오류 화면을 첨부할 때는 계정 정보나 개인 식별 문구가 보이지 않게 가린 뒤 전달하세요. **초기화는 원인을 좁힌 뒤에도 필요한 경우에만** 고려하면 됩니다.
