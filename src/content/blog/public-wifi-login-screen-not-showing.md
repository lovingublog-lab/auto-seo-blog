공항이나 카페에서 와이파이 표시에는 연결됐다고 나오는데 웹페이지는 열리지 않는 경우가 있습니다. 이때 비밀번호를 다시 입력하거나 네트워크를 바로 삭제하면 오히려 원인을 찾기 어려워질 수 있습니다. 공용 와이파이는 **무선망에 붙는 단계**와 **이용 약관·객실번호·이메일 같은 정보를 확인해 인터넷 사용을 허용하는 단계**가 따로 있기 때문입니다.

브라우저에 뜨는 이 인증 화면을 흔히 캡티브 포털(captive portal)이라고 부릅니다. 문제를 풀 때는 휴대폰 설정을 많이 바꾸기보다 **와이파이 연결 → 로그인 화면 → 인증 완료 → 실제 인터넷 접속** 가운데 어디에서 멈췄는지부터 구분하는 것이 빠릅니다.

## 와이파이 아이콘이 보여도 인터넷 사용이 허용됐다는 뜻은 아니다

공용 와이파이 이름을 누른 뒤 연결 표시가 생겼다면 기기와 무선 공유기 사이의 연결은 된 상태일 수 있습니다. 하지만 시설이 별도의 로그인 화면을 운영한다면 인증이 끝나기 전까지 일반 인터넷 접속은 막힐 수 있습니다.

먼저 현재 연결된 네트워크 이름이 안내문에 적힌 공식 와이파이와 같은지 확인합니다. 비슷한 이름의 다른 네트워크에 붙어 있거나 예전에 저장한 네트워크가 자동 연결된 상태라면 로그인 화면을 기다려도 나타나지 않을 수 있습니다.

그다음 브라우저를 새로 열어 평소 방문하는 사이트 하나를 직접 열어봅니다. 자동 로그인 창이 사라졌더라도 웹 요청을 계기로 인증 화면이 다시 나타나는 경우가 있습니다. 여기서 중요한 것은 여러 앱을 동시에 새로고침하는 것이 아니라 **브라우저 한 곳에서 화면이 전환되는지 보는 것**입니다.

## 로그인 화면이 떴다면 주소보다 요구하는 정보의 성격을 본다

공용 와이파이 포털은 시설마다 형태가 다릅니다. 약관 동의만 받는 곳도 있고 객실번호, 예약 정보, 문자 인증처럼 추가 확인을 요구하는 곳도 있습니다.

다만 화면이 떴다는 이유만으로 아무 정보나 입력해서는 안 됩니다. 안내받은 시설명과 전혀 다른 이름이 보이거나, 와이파이 이용과 관계없는 계정 비밀번호·금융정보를 요구하거나, 브라우저가 인증서 위험 경고를 표시한다면 접속을 중단하는 편이 안전합니다.

시설 직원이나 공식 안내문에서 네트워크 이름과 로그인 방법을 다시 확인할 수 있다면 그 경로가 우선입니다. **공용 와이파이를 쓰기 위해 평소 쓰는 이메일·SNS 비밀번호를 입력해야 한다고 가정하지 마세요.**

## 예전에 쓴 네트워크라면 ‘연결됨’ 상태가 오래된 인증을 가릴 수 있다

호텔이나 공항처럼 다시 방문하는 장소에서는 기기가 저장된 와이파이에 자동으로 붙을 수 있습니다. 문제는 네트워크 연결 정보는 남아 있어도 이전 이용 세션이나 인증은 이미 끝났을 수 있다는 점입니다.

이럴 때는 와이파이를 껐다 켜기 전에 현재 네트워크를 한 번 끊었다가 다시 선택해 봅니다. 로그인 화면이 다시 나타난다면 무선 신호 문제가 아니라 인증 세션이 새로 필요했던 상황에 가깝습니다.

반대로 다시 연결해도 로그인 화면이 전혀 나오지 않고 다른 사람도 같은 네트워크에서 인터넷을 쓰지 못한다면 내 기기 설정보다 시설 네트워크 쪽 문제일 가능성도 생각해야 합니다. 한 기기에서만 생기는 문제인지, 같은 장소의 여러 기기에서 동시에 생기는지 비교하면 범위를 빨리 줄일 수 있습니다.

## VPN·보안 연결은 모두 끄기보다 한 가지씩 비교한다

VPN, 사설 DNS, 일부 프라이버시 기능은 평소에는 도움이 되지만 공용 와이파이 로그인 페이지를 여는 과정과 충돌하는 경우가 있습니다. 그렇다고 관련 기능을 한꺼번에 모두 끄면 무엇이 원인이었는지 알기 어렵고, 원래 보안 상태로 되돌리는 것도 놓치기 쉽습니다.

시설의 공식 네트워크가 맞다는 것을 확인한 뒤에도 포털만 열리지 않는다면, 현재 사용 중인 VPN 같은 별도 네트워크 기능을 **하나만 잠시 중지하고 로그인 화면이 나타나는지 비교**합니다. 변화가 없다면 원래 상태로 되돌린 뒤 다음 항목을 확인합니다.

업무용 기기처럼 조직 정책으로 VPN이나 보안 연결을 강제하는 장치는 임의로 우회하지 마세요. 회사에서 허용한 연결 방식이나 모바일 데이터 같은 대체 경로를 쓰는 것이 맞습니다.

## 네트워크 삭제는 마지막에 한다

저장된 네트워크를 삭제하고 다시 연결하면 오래된 연결 정보가 초기화되어 문제가 풀릴 수 있습니다. 하지만 이 단계는 와이파이 비밀번호나 별도의 로그인 정보가 다시 필요할 수 있으므로 초반에 할 이유는 없습니다.

다음 상태가 모두 확인됐는데도 한 기기에서만 접속이 안 될 때 네트워크 삭제를 고려할 수 있습니다.

1. 공식 네트워크 이름이 맞다.
2. 무선 신호에는 연결된다.
3. 로그인 화면이 안 뜨거나 인증 뒤에도 인터넷이 안 된다.
4. 다른 기기는 같은 장소에서 정상적으로 접속된다.
5. 잠시 중지해 본 VPN 등 별도 연결 기능이 원인이 아니었다.

삭제 후에는 안내받은 네트워크를 새로 선택하고 로그인 절차를 처음부터 다시 진행합니다. 이때도 한 단계씩 확인해야 어느 지점에서 다시 막히는지 알 수 있습니다.

## 연결돼도 민감한 작업까지 공용망에서 해야 하는 것은 아니다

로그인이 정상적으로 끝났다고 해서 그 네트워크의 운영 주체와 보안 수준을 완전히 알 수 있는 것은 아닙니다. 금융 거래, 중요한 업무 계정 변경, 민감한 자료 전송처럼 실패 비용이 큰 작업은 신뢰할 수 있는 개인 네트워크나 모바일 데이터로 미루는 선택지도 있습니다.

공용 와이파이 문제를 해결하는 기준은 설정을 많이 바꾸는 데 있지 않습니다. **공식 네트워크 확인 → 포털 호출 → 인증 상태 확인 → 다른 기기와 비교 → 별도 네트워크 기능을 하나씩 점검 → 마지막에 저장 네트워크 재설정** 순으로 범위를 좁히면 불필요한 변경을 줄이면서 막힌 지점을 찾기 쉽습니다.
